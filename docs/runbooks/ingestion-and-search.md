# Runbook: Knowledge Ingestion & Hybrid Search Retrieval

This runbook guides Knowledge Contributors and Consumers through creating repositories, ingesting complex documents (PDFs, markdown, text), monitoring background ARQ queue processing, and executing Reciprocal Rank Fusion (RRF) hybrid searches.

---

## 1. Creating a Knowledge Repository

Repositories act as logical containers for grouping related documents within an organization.
Create a repository via the REST API:
```bash
export ASILA_API_KEY="<your_api_key>"
export ORG_ID="<your_org_id>"

curl -X POST "http://localhost:8000/api/v1/knowledge/repositories" \
     -H "Content-Type: application/json" \
     -H "X-Asila-API-Key: $ASILA_API_KEY" \
     -H "X-Organization-Id: $ORG_ID" \
     -d '{
       "name": "Engineering Architecture Specs",
       "connector_type": "local",
       "external_id": "repo-eng-specs-001"
     }'
```

## 2. Document Ingestion Pipeline

### Step 1: Ingest Local Documents via CLI
Use the Typer CLI to recursively collect and upload files from a local directory or single file:
```bash
python3 -m cli.main ingest \
    --path ./docs/ \
    --repo-id "<repository_id>" \
    --api-key "$ASILA_API_KEY"
```
*How it works: The CLI uploads file contents to `POST /api/v1/knowledge/documents`. The backend persists the file, creates a `Document` entity with `status = 'processing'`, and enqueues an asynchronous parsing job in Redis.*

Check the overall indexing status of your knowledge base:

## 3. Monitoring Ingestion Jobs & Circuit Breakers

Aasila processes documents in background worker containers (`workers/core.py`) using Docling OCR and vector embedding providers.

### Step 1: Inspect Specific Job Status
If a document remains in `processing` or switches to `failed`, inspect its durable job state:
```bash
python3 -m cli.main jobs get "<job_id>"
```
**Expected Output for a Completed Job**:

### Step 2: Understanding Circuit Breaker Failures
If the external Docling OCR container crashes or times out, the asynchronous circuit breaker in `service.py` trips after 5 consecutive failures:
* **Status**: `job.status` transitions to `failed`.
* **Error Detail**: `job.last_error` records `CircuitBreakerError: Circuit breaker 'call_docling' is OPEN`.
* **Remediation**: Check Docling health via `asila doctor`, resolve container memory constraints, and re-run ingestion once the recovery timeout expires.

## 4. Executing Hybrid Search & RRF Ranking

Aasila combines two distinct retrieval strategies into a unified ranking model using Reciprocal Rank Fusion (RRF):
1. **Semantic Search (`pgvector`)**: Cosine similarity against vector embeddings generated by Ollama/OpenAI.
2. **Keyword Search (`tsvector`)**: Full-text English lexeme matching with PostgreSQL GIN indexing.

### Execute Hybrid Search via CLI
Run a hybrid query from your terminal:
```bash
python3 -m cli.main search \
    --query "multi-tenant RLS isolation invariants" \
    --mode hybrid \
    --limit 5
```
**Expected Output**:
```
Search Results
================================================================================
1. [Score: 0.0321] Aasila Current System Map (doc_a1b2...)
   Snippet: ...enforced at the database engine layer via PostgreSQL Row-Level Security (RLS)...
--------------------------------------------------------------------------------
2. [Score: 0.0284] Security Invariant Verification (doc_e5f6...)
   Snippet: ...no caller-controlled organization_id override paths exist in application...
================================================================================
```

### Execute Hybrid Search via REST API
```bash
curl -X GET "http://localhost:8000/api/v1/knowledge/retrieval/search?query=security+gate&mode=hybrid&limit=5" \
     -H "X-Asila-API-Key: $ASILA_API_KEY" \
     -H "X-Organization-Id: $ORG_ID"
```
*Note: Every search request is wrapped in a transaction-local RLS context (`SET LOCAL asila.current_organization_id = '<org_id>'`), guaranteeing that consumers never see search snippets from other tenants.*
